# Развёртывание собственного сервера МУЛЬТИК ТВ

Этот пакет запускается на отдельной Linux-машине с Docker Compose. Он не создаёт облачный аккаунт и не включает эфир сам по себе.

## Состав
- SRS принимает RTMP и формирует HLS.
- Node.js API показывает состояние канала.
- FFmpeg-директор воспроизводит только файлы из расписания с `rightsCleared: true`.
- Docker volumes сохраняют видео, расписание и HLS между перезапусками.

## Перед началом
1. Взрослый владелец проекта выбирает хостинг и проверяет тариф, лимиты трафика и условия бесплатного использования. «Бесплатно навсегда» не гарантируется.
2. Используйте поддерживаемый Ubuntu LTS на выделенной виртуальной машине.
3. Установите Docker Engine и Docker Compose plugin по официальной инструкции Docker.
4. API по умолчанию привязан только к `127.0.0.1:8080` на хосте. Это намеренно: не меняйте привязку на публичный интерфейс, пока взрослый администратор не установит HTTPS reverse proxy и контроль доступа. Не открывайте Docker socket.
5. Для постоянного эфира проверьте разрешённый входящий RTMP (1935), исходящий трафик и правила firewall у провайдера.

## Запуск
Из каталога `cloud-server`:
```sh
docker compose config
# После размещения видео и schedule.json выполните предэфирную проверку:
docker compose run --rm --entrypoint node api preflight.js
docker compose up -d --build
docker compose ps
```

Проверка API на самой машине (порт 8080 извне недоступен по умолчанию):
```sh
curl -fsS http://127.0.0.1:8080/health
curl -fsS http://127.0.0.1:8080/api/channel
```

Ожидайте JSON со статусом API. Наличие работающего API **не означает**, что идёт видеотрансляция: для этого необходимы разрешённые видеофайлы и созданный HLS-плейлист.

## Добавление медиаматериалов и расписания
Сначала создайте папку/том для медиа и поместите туда видео, права на публичный показ которых подтверждены. Затем заполните том расписания файлом `schedule.json`:
```json
{
  "items": [
    {
      "title": "Название программы",
      "file": "program.mp4",
      "rightsCleared": true
    }
  ]
}
```
Значение `rightsCleared: true` — подтверждение оператора, а не автоматическая проверка лицензии системой. Не включайте материал, пока права не проверены.

## Адреса после настройки домена и HTTPS
- API: `https://ВАШ-ДОМЕН/health`
- HLS: `https://ВАШ-ДОМЕН/hls/live/multiktv.m3u8`
- RTMP ingest: `rtmp://ВАШ-ДОМЕН/live/multiktv` (только если провайдер и firewall разрешают RTMP)

## Проверка и обслуживание
```sh
docker compose logs --tail=100 api
docker compose logs --tail=100 director
docker compose logs --tail=100 video
docker compose restart
```

Не публикуйте логи с секретами. Не отправляйте пароли, SSH-ключи, токены или платёжные данные в чат.

## Важные ограничения
- GitHub Pages хранит статические файлы, но не запускает Docker/FFmpeg и не является видеосервером.
- Бесплатный тариф хостинга может иметь лимиты CPU, RAM, диска, исходящего трафика и доступности.
- До публичного запуска взрослый администратор должен настроить обновления ОС, firewall, HTTPS, резервные копии и защиту API.
- Поиск каталога Internet Archive возвращает метаданные; он не скачивает видео и не даёт права на ретрансляцию.
