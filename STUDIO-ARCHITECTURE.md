# МУЛЬТИК ТВ Studio — архитектура

## Цель
Собственный сервис управления телеканалом: веб-пульт, видеотека, плейлист, расписание, статус эфира и API. Это отдельный backend, а не только статическая страница GitHub Pages.

## Принцип
Не писать видеокодек и playout-движок с нуля. Использовать ffplayout (open-source) как проверяемый движок вещания, а собственный сервис строить вокруг него: API, авторизация, очередь, расписание, мониторинг и интеграции.

## Компоненты
- Web UI: текущий GitHub Pages проект, постепенно превращаемый в Studio.
- Backend API: Node.js service; все административные операции только после серверной авторизации.
- Database: PostgreSQL для пользователей, медиа-метаданных, плейлистов, расписания и журналов.
- Media storage: отдельное объектное хранилище; не хранить большие видео в GitHub.
- Playout worker: ffplayout на постоянно работающем Linux-сервере.
- Output: HLS для сайта и/или RTMP/RTMPS для Kinescope, после проверки совместимости.
- Integrations: GitHub webhook/Actions для обновления кода; Kinescope API только через сервер и только с официальными ключами.

## API (план)
- GET /api/health — здоровье backend.
- GET /api/status — состояние движка и текущий элемент.
- GET /api/playlist — список элементов.
- PUT /api/playlist — заменить очередь после проверки прав доступа.
- POST /api/media — зарегистрировать/загрузить медиа с проверкой типа и размера.
- POST /api/schedule — создать или изменить расписание.
- POST /api/playout/start — запуск, только для авторизованного администратора.
- POST /api/playout/stop — остановка, только для авторизованного администратора.
- GET /api/events — журнал событий/статусов.

## Безопасность и права
- Не размещать API-ключи, RTMP-ключи, пароли или service-role secrets в GitHub Pages, исходниках или GitHub Actions logs.
- Использовать серверную авторизацию, роли и ограничение запросов.
- В очередь допускаются только видео, на которые есть права показа; хранить источник и сведения о лицензии.
- Для публичного детского канала включить модерацию перед публикацией.

## Реальные ограничения
- Программа ffplayout бесплатна, но круглосуточный сервер, исходящий видеотрафик и хранилище могут требовать оплаты.
- Нельзя обещать бесплатный 24/7 без найденного хостинга с достаточными ресурсами и безлимитным/достаточным трафиком.
- Сначала тестировать локально или на тестовом окружении; не переключать действующий эфир без отдельной проверки.
- До подтверждения бюджета и владельца инфраструктуры не создавать платные облачные ресурсы.

## Этапы
1. Проверить и зафиксировать интерфейс/контракт ffplayout, формат плейлиста и поддерживаемые выходы.
2. Реализовать backend API и безопасную авторизацию.
3. Сделать адаптер playout engine и тесты на локальном тестовом потоке.
4. Подключить видеотеку и метаданные лицензий.
5. Подключить мониторинг и Kinescope после проверки API/тарифных условий.
6. Развернуть на выбранном сервере после подтверждения взрослым владельцем аккаунта и проверки возможных расходов.

## Текущий статус
Это архитектурный план. Backend, хранилище и playout worker ещё не развернуты; действующий GitHub Pages сайт сам по себе не вещает 24/7.
