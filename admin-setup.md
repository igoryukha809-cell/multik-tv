# Административный доступ — переход на VK ID

## Текущий статус

Новая авторизация VK ID пока не подключена к серверным административным маршрутам. Ветка `rebuild-vkid-auth` содержит страницу входа и документацию; действующие серверные проверки в этой ветке всё ещё используют Logto.

Не считайте VK ID уже работающим и не удаляйте Logto до завершения миграции.

## Целевая модель доступа

- VK ID подтверждает пользователя.
- Сервер самостоятельно проверяет VK ID access token через официальный UserInfo endpoint.
- Сервер связывает сессию с числовым VK user ID.
- Административные права определяются только серверным списком `VK_ADMIN_USER_IDS`.
- Обычный вход через VK ID не даёт автоматически права администратора.
- Ключи API для технических операций остаются отдельными от пользовательской сессии.

## Обязательные серверные меры

- Постоянное хранилище сессий; не хранить сессии в памяти процесса или в публичном репозитории.
- Случайный непрозрачный идентификатор сессии в cookie с флагами `HttpOnly`, `Secure` и подходящим `SameSite`.
- Защита изменяющих запросов от CSRF и проверка точного Origin.
- Проверка роли на каждом административном API-маршруте, а не только в HTML.
- Ограничение частоты попыток входа; не писать токены и cookie в логи.

## Блокирующие настройки

1. VK ID App ID и точный callback URL из кабинета приложения.
2. Числовой VK ID администратора или администраторов.
3. Выбранная схема общего домена/API-прокси для cookie-сессий.
4. Настроенное постоянное хранилище сессий и секреты окружения на сервере.

Не отправляйте пароли, access token, refresh token, cookie или секреты в чат или GitHub.

## Текущая legacy-интеграция

`admin-guard.js`, `admin.html`, `access-keys.html`, `storage-api/server.js` и `cloud-server/server.js` ещё содержат Logto-код. До завершения VK ID миграции эта конфигурация не считается удалённой или заменённой.
