# Интеграция МУЛЬТИК ТВ Studio с ffplayout

Документ основан на официальной документации:
- API: https://github.com/ffplayout/ffplayout/blob/main/docs/api.md
- Установка: https://github.com/ffplayout/ffplayout/blob/main/docs/install.md
- Возможности: https://github.com/ffplayout/ffplayout

## Выбранная схема

Мы НЕ разрабатываем собственный видеоплеер или движок вещания. ffplayout отвечает за playout и выходной поток. Наш Studio-пульт будет отдельным интерфейсом управления, который обращается к ffplayout через защищённый backend-адаптер.

## Подтверждённые возможности ffplayout

- Встроенные web frontend и API; по умолчанию локальный адрес 127.0.0.1:8787.
- API использует Bearer access token для защищённых маршрутов.
- Встроенная авторизация: login, refresh, logout; поддерживаются роли global admin, channel admin и user.
- Получение и сохранение плейлистов, генерация плейлиста по шаблону.
- Управление воспроизведением: previous/next/reset, получение текущего медиа и состояния, start/stop/restart процесса.
- Загрузка файлов частями с возможностью продолжения прерванной загрузки.
- Выходы HLS, RTMP/RTMPS, SRT и другие поддерживаемые FFmpeg transports; точные кодеки зависят от сборки.
- Встроенные события через SSE для состояния playout и системы.
- Зацикливание плейлиста и автоматическое заполнение эфира filler-клипами, если это настроено.

## API-методы для адаптера

Все пути ниже относятся к ffplayout API. Большинство требуют Authorization: Bearer ACCESS_TOKEN.

| Задача Studio | Метод ffplayout | Назначение |
|---|---|---|
| Вход в движок | POST /auth/login | Получить access/refresh tokens |
| Обновить сессию | POST /auth/refresh | Ротация токенов |
| Список каналов | GET /api/channels | Каналы, доступные пользователю |
| Текущий эфир | GET /api/control/{id}/media/current | Текущее видео и состояние |
| Состояние процесса | POST /api/control/{id}/process | status/start/stop/restart |
| Следующий ролик | POST /api/control/{id}/playout | control=next |
| Предыдущий ролик | POST /api/control/{id}/playout | control=back |
| Очередь на дату | GET /api/playlist/{id}?date=YYYY-MM-DD | Прочитать плейлист |
| Сохранить очередь | POST /api/playlist/{id} | Сохранить JSON плейлиста |
| Сгенерировать очередь | POST /api/playlist/{id}/generate/{date} | Создать по шаблону |
| Видеотека | POST /api/file/{id}/browse | Просмотр папок/файлов |
| Загрузка | PUT /api/file/{id}/upload?path=... | Chunked multipart upload |
| Системная статистика | GET /api/system/{id} | Статистика канала |

## Архитектура безопасности

Браузерный Studio-пульт не должен обращаться к открытому ffplayout API напрямую и не должен хранить пароль, refresh token или bearer token в исходниках/репозитории.

Рекомендуемый поток:
1. Пользователь входит в Studio через собственную серверную авторизацию.
2. Backend проверяет роль администратора.
3. Backend обращается к ffplayout API по приватной сети или через защищённый reverse proxy.
4. Backend хранит секреты только в переменных окружения/секрет-хранилище.
5. Backend отдаёт Studio только минимально необходимый статус и выполняет разрешённые действия.

Не выставлять порт 8787 открытым в Интернет без TLS, сильной авторизации, ограничений доступа и настройки reverse proxy. Официальная инструкция ffplayout рекомендует reverse proxy с SSL для публичного доступа.

## Kinescope

ffplayout документирует RTMP/RTMPS выходы. Возможность отправки потока в конкретный Kinescope ingest endpoint должна быть проверена тестовой трансляцией и по текущей документации Kinescope. Потоковые ключи хранить только на backend, не в GitHub Pages, GitHub Issues или логах.

## Следующий технический этап

Реализовать backend-адаптер с маршрутами Studio:
- GET /api/studio/status
- GET /api/studio/playlist?date=...
- PUT /api/studio/playlist
- POST /api/studio/playout/start
- POST /api/studio/playout/stop
- POST /api/studio/playout/next
- GET /api/studio/media

Каждый маршрут должен требовать серверную авторизацию и проксировать только разрешённые операции в ffplayout. Перед реализацией необходимо зафиксировать версию ffplayout и протестировать формат конфигурации/плейлиста на тестовом сервере.

## Важные условия

ffplayout — готовый движок вещания, а не бесплатный облачный хостинг. Его программное обеспечение открытое, но сервер, хранение и передача видео могут иметь стоимость. Не создавать облачные ресурсы с возможной оплатой без согласия взрослого владельца аккаунта.
