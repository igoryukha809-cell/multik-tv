# МУЛЬТИК ТВ — облачный план на бесплатном ARM-сервере

Этот документ готовит проект к переносу на собственную виртуальную машину. Он **не создаёт аккаунт, не заказывает VM и не запускает эфир автоматически**.

## Выбранный класс сервера

Кандидат — Oracle Cloud Infrastructure Always Free, Compute VM.Standard.A1.Flex (Arm). Официальная квота может включать до 4 OCPU и 24 GB RAM суммарно по A1 в пределах Always Free (конкретная доступность зависит от региона и свободной ёмкости). Это заметно мощнее домашнего мини-сервера, но не является гарантией доступности или непрерывности эфира. Проверяйте актуальные лимиты на официальной странице: https://www.oracle.com/cloud/free/ и https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier.htm

**Важно:** бесплатная квота не означает, что ресурсы всегда доступны. При регистрации Oracle обычно требует подтверждение личности и платёжную карту; несовершеннолетний не должен самостоятельно оформлять и администрировать такой аккаунт. Это должен делать родитель/опекун. Не переходите на платный тариф и не вводите платёжные данные в сторонние инструкции.

## Архитектура

- SRS — приём потока и выдача HLS.
- FFmpeg — циклическое воспроизведение подготовленных видео.
- Docker Compose — запуск компонентов и перезапуск после сбоев.
- HLS — просмотр через веб-плеер канала.
- GitHub Pages остаётся сайтом и плеером; он не является видеосервером.

## Подготовка VM (выполняет взрослый владелец аккаунта)

Создайте Ubuntu Server LTS ARM64 VM только в пределах явно указанной бесплатной квоты. Не выбирайте платные диски, дополнительные IP, балансировщики или коммерческие образы. Перед подтверждением проверьте, что итоговая оценка стоимости равна $0.

После создания VM владелец должен безопасно подключиться по SSH и установить Docker Engine и Compose plugin по официальной инструкции Docker для Ubuntu: https://docs.docker.com/engine/install/ubuntu/

Затем:
1. Клонировать репозиторий и перейти в `stream-server/`.
2. Поместить в `media/` только собственные видео или материалы с документально подтверждённым разрешением на публичный показ.
3. Проверить поддержку ARM64 у используемых Docker-образов и успешно выполнить тестовую сборку/запуск. Не считать архитектурную совместимость подтверждённой до проверки.
4. Запустить `docker compose up -d --build` и проверить `docker compose ps` и логи.
5. Настроить HTTPS-доступ к HLS через защищённый reverse proxy. Не выставлять RTMP-порт, Docker API или административные интерфейсы в интернет без отдельной безопасной настройки.
6. Проверить эфир с внешней сети и мониторить трафик/квоты. Исходящий видеотрафик растёт с каждым зрителем.

## Проверки перед публикацией

- [ ] Владелец аккаунта подтвердил бесплатную конфигурацию и стоимость $0.
- [ ] VM ARM64 действительно запущена и не имеет платных ресурсов.
- [ ] Все Docker-образы поддерживают ARM64.
- [ ] В папке `media/` есть разрешённые материалы.
- [ ] SRS и FFmpeg работают без ошибок.
- [ ] HLS открывается через HTTPS.
- [ ] Нет открытых лишних портов и секретов в репозитории.
- [ ] Проверены ограничения исходящего трафика и возможная политика простоя.
