# Вход через VK ID (подготовка)

Веб-приложение использует Logto как центральный сервис сессий и проверки доступа. Вход для пользователя планируется через VK ID; GitHub больше не используется как кнопка входа.

## Что уже подготовлено в ветке rebuild-vk-auth

- Страница `login.html` вызывает Logto с `directSignIn: "social:vk"`.
- Страница ключей доступа показывает VK ID вместо GitHub.
- Административный API поддерживает точную проверку `sub` пользователя Logto через переменную `ADMIN_LOGTO_SUBJECT`. Это предпочтительнее email: VK ID не обязан предоставлять подтверждённый email.
- Админские операции по-прежнему проверяются сервером, а не значением из браузера.

## Важная совместимость протоколов

VK ID использует актуальный OAuth 2.1-поток с PKCE и параметрами, которые могут отличаться от обычного OAuth 2.0 Authorization Code. Встроенный OAuth 2.0-коннектор Logto документирован для Authorization Code. Поэтому нельзя считать, что простое заполнение стандартных URL автоматически заработает с VK ID.

Перед публикацией нужно проверить совместимость выбранного VK ID приложения с OAuth-коннектором Logto. Не включайте старый OAuth endpoint наугад и не ослабляйте проверку токенов. Если Logto не поддержит нужный поток VK ID, потребуется отдельный совместимый VK ID connector для Logto либо согласованная смена архитектуры авторизации.

## Что требуется от владельца приложения

1. Создать веб-приложение VK ID в официальном кабинете разработчика.
2. После выбора поддерживаемого способа интеграции добавить точный Redirect URI, который выдаст Logto.
3. В Logto Console открыть Connectors → Social connectors и добавить VK-коннектор, если выбранный VK ID flow совместим.
4. Указать ID приложения и секрет только в защищённых настройках коннектора Logto. Не добавлять секреты в GitHub, HTML, JavaScript или переписку.
5. Включить коннектор в Sign-in & account → Sign-up and sign-in → Social sign-in и задать уникальное имя провайдера `vk`.
6. Выполнить тестовый вход и убедиться, что callback возвращает пользователя в сайт.

## Включение прав администратора

После первого успешного тестового входа владелец сервера должен получить Logto user ID (`sub`) из проверенного токена и задать его в защищённых переменных backend:

- `ADMIN_LOGTO_SUBJECT` — точный Logto subject администратора.
- `LOGTO_ENDPOINT` — endpoint существующего Logto tenant.
- `LOGTO_API_RESOURCE` — audience API.

Не назначайте права администратору только по имени, VK-нику, email из браузера или локальному хранилищу. Не публикуйте JWT, client secret или приватные ключи.

## Статус

Подготовка кода в ветке не означает, что VK ID уже подключён. Для завершения нужны созданное VK ID приложение, настройка совместимого коннектора в Logto и серверные переменные. До успешной проверки сайт не должен показывать, что вход или административная авторизация работают.
