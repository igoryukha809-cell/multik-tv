# Общий сервер авторизации VK ID

Это отдельный серверный компонент для будущего входа VK ID. Он пока не подключён к публичному сайту и не заменяет действующую авторизацию.

## Что реализовано в заготовке

- Проверка access token запросом к VK ID UserInfo с серверной стороны.
- Числовой VK user ID берётся только из ответа VK ID, а не из браузера.
- Случайная непрозрачная сессия в cookie `__Host-vkid_session` (`HttpOnly; Secure; SameSite=Lax`).
- Хранение только SHA-256-хеша сессии в PostgreSQL, срок действия — 7 дней.
- Администраторский доступ по серверному списку `VK_ADMIN_USER_IDS`.
- Отдельный внутренний endpoint для проверки сессии двумя API.
- Проверка Origin, ограничение размера JSON, базовое ограничение частоты запросов и CSRF-токен для выхода.

## Переменные окружения

Настраиваются только в серверном хостинге, не в GitHub Pages и не в репозитории:

- `DATABASE_URL` — приватная строка подключения к PostgreSQL.
- `VKID_APP_ID` — числовой ID приложения VK ID.
- `VKID_API_ORIGIN` — HTTPS origin VK ID из актуальных настроек/документации, без пути. Он намеренно не зашит в код.
- `PUBLIC_SITE_ORIGIN` — точный origin сайта, например `https://www.example.com`.
- `SESSION_COOKIE_DOMAIN` — общий родительский домен для сайта и API, например `.example.com`. Он обязателен: auth-service и обе API должны быть под этим доменом или за общим reverse proxy. Для `github.io` так сделать нельзя.
- `AUTH_SERVICE_SECRET` — длинный случайный секрет для связи API с auth-service.
- `VK_ADMIN_USER_IDS` — список числовых VK ID администраторов через запятую.
- `PORT` — необязательный порт (по умолчанию 8080).

PostgreSQL должен использовать TLS. Временное отключение проверки сертификата не предусмотрено. Для локальной разработки используйте отдельную тестовую базу и явно документированную TLS-конфигурацию.

## API

- `POST /api/auth/vk/session` — принимает только access token, проверяет его у VK ID, создаёт cookie-сессию.
- `GET /api/auth/session` — возвращает статус сессии и серверный флаг `isAdmin`.
- `GET /api/auth/csrf` — выдаёт CSRF-токен для текущей сессии.
- `POST /api/auth/logout` — отзывает сессию; требует Origin и CSRF.
- `GET /internal/session` — внутренняя проверка; требует `Authorization: Bearer AUTH_SERVICE_SECRET` и cookie сессии.

## Важные ограничения перед запуском

1. У VK ID должен быть зарегистрирован точный callback URL. Клиентский SDK требует реальный App ID.
2. `VKID_API_ORIGIN` нужно установить по актуальной конфигурации VK ID приложения; не используйте устаревший домен.
3. Фронтенд и API должны работать в совместимой first-party cookie схеме (например, на одном собственном сайте с поддоменами). GitHub Pages на `github.io` и произвольный API-домен не дают гарантии доступности cookie в браузерах.
4. Оба API должны обращаться к этому сервису по приватному адресу, передавая cookie пользователя и внутренний секрет. Пока эта интеграция не выполнена, текущие административные маршруты продолжают использовать старую проверку.
5. Перед реальным развёртыванием нужны тесты на мобильных и настольных браузерах, проверка VK ID приложения, секретов, PostgreSQL и TLS.

## Безопасное состояние

Кнопка VK ID на сайте должна оставаться выключенной. Не удаляйте Logto и не меняйте production, пока общий сервис, обе API, callback и браузерные тесты не пройдут проверку.
